# Frequency-dependent RF switching

## Scope

This document follows the two indices generated by `FUN_0802c840`
from the tuned frequency into their physical output mechanisms. It
documents bit patterns, not final relay or filter names: no schematic
evidence currently identifies the individual controlled nets.

## Update order

When the tuned frequency crosses a region boundary, `FUN_0802c840`
updates:

- primary RF index at main-state offset `+0x6A`, setting pending bit 1;
- secondary sub-band index at offset `+0x6B`, setting pending bit 0;
- the frequency-dependent DAC2 code.

The VFO update path then:

1. calculates and caches the new LO divider;
2. requests a DSP-state reset and starts a four-block transition
   counter;
3. applies the primary index;
4. applies the secondary index;
5. adjusts the approximately 2 MHz `PSYNC` candidate;
6. commits the cached LO divider.

Ordering and pending-bit behavior: VERIFIED.

## DSP transition handling

Immediately before applying pending RF outputs, `FUN_080243d0` writes
one to byte `0x20008328`. On the next DMA1 Stream 3 DSP invocation,
`FUN_08024528` clears this flag and resets numerous filter histories,
delay buffers, accumulators, and related state. Request/consume
behavior and bulk state clearing: VERIFIED.

`FUN_08023d4c` operates on byte `0x2000832A`. If it is zero, the
function changes its local value to 4, executes a 100-iteration
register-only loop, and stores 4. If it was already nonzero, it retains
that value. The DMA handler decrements the byte once at the end of each
processed block until it reaches zero: VERIFIED.

Despite the decompiler's higher-level rendering, the instruction stream
does not reload `0x2000832A` inside the 100-iteration loop. Therefore
`FUN_08023d4c` is not a synchronous wait for four DMA interrupts:
VERIFIED. Describing it as a four-block transition/countdown marker is
HIGH CONFIDENCE; no other consumer was found that changes DSP gain or
hardware state based on its current value.

`FUN_08023d74`, called with `0x14` before some adjacent gain/control
changes, immediately returns and ignores its argument in BASE 1.1.9.
It must not be reimplemented as a 20 ms delay without evidence from
another firmware build: VERIFIED.

This establishes a DSP discontinuity-control role for the sequence,
not a separately observed hardware mute. Whether other callbacks around
RX/TX transitions electrically mute the RF path is a separate question.
Direct-reference evidence for the two bytes is exported in
`analysis/rf_switching/dsp_handshake_refs.csv`.

RX/TX transitions use another dirty flag and reset path. Their first
digital input gain is documented separately in `docs/tx_pipeline.md`;
it is not changed by ordinary frequency switching.

## Primary RF index

The frequency-to-index regions are documented in
`docs/frequency_control.md`. The index is emitted by a callback selected
during `FUN_0803131c` initialization. Two output implementations are
present.

### I2C2 GPIO-expander implementation

The object at `0x20000360` uses I2C address byte `0x40`, conventional
7-bit address `0x20`. Startup reads registers 2 through 7, and later
writes output registers 2 and 3 as a 16-bit state.

Address, register accesses, and 16-bit behavior match the NXP PCA9535
family: HIGH CONFIDENCE. The primary reference is the
[NXP PCA9535/PCA9535C datasheet](https://www.nxp.com/docs/en/data-sheet/PCA9535_PCA9535C.pdf).
An exact package suffix cannot be recovered from firmware.

Before selecting a region, `FUN_080311a8` clears mask `0x3BF8` and then
sets one region-specific bit:

| RF index | PCA9535 output mask |
| ---: | ---: |
| 0 | `0x0800` |
| 1 | `0x0100` |
| 2 | `0x0200` |
| 3 | `0x1000` |
| 4 | `0x2000` |
| 5 | `0x0080` |
| 6 | `0x0040` |
| 7 | `0x0020` |
| 8 | `0x0010` |
| 9 | `0x0008` |

Masks and one-hot behavior: VERIFIED. Values are reproducibly exported
from `0x0803D0E8` by `tools/run_headless_data_words.sh`; raw output is
in `analysis/rf_switching/rf_band_masks.csv`.

### Direct-GPIO implementation

If the expander probe does not select the first implementation,
`FUN_08030af8` encodes the same index as four binary GPIO outputs:

| Weight | GPIO |
| ---: | --- |
| 1 | PD9 |
| 2 | PD10 |
| 4 | PD11 |
| 8 | PD13 |

The bit values are written through the STM32 GPIO set/reset register.
For example, index 5 drives PD11 and PD9 high and PD13/PD10 low.
Mapping and binary encoding for indices 0–9: VERIFIED.

The firmware therefore supports two RF-control board implementations:
one-hot outputs through an I2C2 PCA9535-compatible expander, or a
four-bit binary code directly on GPIOD. This compatibility behavior is
VERIFIED. Which electrical board revision uses each implementation is
unknown.

## Secondary sub-band index

`FUN_0802c750` clears bits 7–13 in a shared 24-bit output image and
sets exactly one. The complete frequency mapping is:

| Frequency region | Secondary index | Output-image bit |
| ---: | ---: | ---: |
| ≤2 MHz | 0 | 13 |
| >2–4 MHz | 1 | 12 |
| >4–8 MHz | 2 | 11 |
| >8–15 MHz | 3 | 10 |
| >15–22 MHz | 4 | 9 |
| >22–30 MHz | 5 | 8 |
| >30 MHz | 6 | 7 |

The image is transmitted as three bytes through SPI6 at `0x40015400`.
The transfer completion path drives PG12 low. One-hot selection,
exact integer boundaries, three-byte transfer, SPI6 peripheral, and
PG12 operation: VERIFIED. The same intervals are included in
`analysis/frequency_control/frequency_bands.csv`.

Interpretation as another bank of RF relays or filter switches is HIGH
CONFIDENCE because the selected bit follows tuned-frequency subregions
and is applied during the RF transition. Individual bit-to-filter
names remain HYPOTHESES and are not assigned.

## Reimplementation implications

- Keep primary index calculation independent from its physical backend.
- Probe the PCA9535-compatible expander before choosing I2C or
  direct-GPIO output.
- Preserve all unrelated PCA9535 output bits when changing the
  `0x3BF8` region mask.
- Preserve unrelated bits in the shared 24-bit SPI6 image.
- Apply RF switching before committing the new LO divider.
- Reset the recovered DSP histories at the next block boundary after a
  frequency/RF-path change.
- Preserve the four-block countdown only if compatibility with the OEM
  state machine requires it; it does not synchronously delay the main
  control path in BASE 1.1.9.
- Do not label any bit as a specific LPF/BPF relay without schematic or
  controlled measurement evidence.

## Remaining work

- Associate PCA9535/direct-GPIO codes with board revisions.
- Identify the physical filters or relays selected by each primary and
  secondary code.
- Determine whether the four-block counter has an external diagnostic
  purpose or is vestigial synchronization logic.
